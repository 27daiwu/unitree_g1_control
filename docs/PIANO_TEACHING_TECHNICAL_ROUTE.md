# G1 钢琴示教技术路线

## 1. 当前阶段与总体原则

G1 弹钢琴项目进入实机播放与示教阶段。经过 Arm SDK 实测，Arm SDK 无法直接用于机器人坐姿状态下的上肢控制。因此，后续坐姿上肢控制不再依赖 Arm SDK，而是在调试模式下自行进行全身电机控制。

底层虽然使用全身电机控制，但运动逻辑必须严格拆分“坐姿基座”和“手臂动作”，不能把 29DoF 当成一条整体轨迹处理：腿部和腰部负责稳定坐姿，双臂负责示教、保持和钢琴动作播放。

## 2. 任务流程

```text
程序启动
  → 用户将机器人调整到目标坐姿
  → 标定 SIT_HOME
  → 手臂从身体两侧进入 ARM_HOME（钢琴起手式）
  → 动作 1 → 动作 2 → 动作 3 → …
  → 回到 ARM_HOME
  → 手臂收回身体两侧 ARM_REST
  → 回到/保持 SIT_HOME
  → 结束控制
```

启动后的 SIT_HOME 必须重新标定，以适应实际座椅、机器人位置和现场姿态变化。ARM_HOME 可以提供默认值，但必须允许用户重新标定。

## 3. 姿态定义

| 姿态 | 用途 | 标定/来源 | 控制范围 |
| --- | --- | --- | --- |
| `SIT_HOME` | 坐姿基准和全程支撑姿态 | 每次启动由用户现场标定 | 仅腿部 + 腰部 |
| `ARM_REST` | 手臂自然放置在身体两侧的安全姿态 | 默认值，可按实机调整 | 双臂 |
| `ARM_HOME` | 双手位于钢琴上方的弹琴准备姿态 | 默认值，必须支持重新标定 | 双臂 |
| `P1`, `P2`, `P3`, … | 示教和演奏动作点 | 在录制时间轴上打点 | 双臂 |

姿态数据应明确记录关节组、时间戳、来源和标定版本，避免将坐姿基座数据与手臂动作数据混为一体。

## 4. 控制架构

```text
Full-body motor control
├─ Legs + Waist: SIT_HOME HOLD
└─ Arms: TEACH / HOLD / PLAYBACK
```

- 腿部和腰部：全过程维持 `SIT_HOME`，使用正常较高刚度，不参与钢琴轨迹，也不进入柔顺示教状态。
- 双臂：根据当前阶段执行 `ARM_REST`、`ARM_HOME`、示教模式或轨迹播放。
- 所有控制循环必须保留明确的关节分组边界；任何手臂轨迹播放都不得覆盖腿部和腰部的 `SIT_HOME` 目标。

## 5. 手臂状态

系统至少包含以下三种手臂状态：

### `TEACH`

有明显阻力但可以人工拖动，用于动作摆位和关键点记录。

### `HOLD`

以较高刚度保持当前或指定点位，用于检查姿态、进入钢琴起手式以及轨迹切换。

### `PLAYBACK`

按照原始录制轨迹或其派生轨迹执行钢琴动作。

状态切换必须有明确的进入和退出条件，切换时应避免目标位置突变；退出示教或播放后，手臂应经过受控过渡回到 `ARM_HOME` 或 `ARM_REST`。

## 6. 示教模式的目标手感

目标物理手感为“有明显阻力的拖动”：

- 松手时手臂基本维持当前位置；
- 施加较明显力量后可以缓慢拖动关节；
- 拖动过程中阻力稳定，不出现明显抖动；
- 松手后不猛烈弹回原位置；
- 手臂不因自重明显下坠或持续漂移。

基础电机位置控制模型为：

```text
τ = Kp(q_target - q) + Kd(dq_target - dq) + τ_ff
```

示教模式不能简单采用高 `Kp` 固定保持进入示教瞬间的位置。第一阶段使用较低到中等 `Kp`、合适 `Kd`，并根据实机结果决定是否加入重力补偿或目标跟随机制。

## 7. 分阶段控制策略

### 7.1 基础方案

1. 进入 `TEACH` 时，将 `q_target` 初始化为当前手臂实际角度 `q`。
2. 将手臂 `Kp` 调低到能够人工拖动但仍有明显支撑力的范围。
3. 使用合适 `Kd` 提供阻尼，抑制拖动后的摆动。
4. 腿部和腰部继续以较高刚度保持 `SIT_HOME`。
5. 实测拖动后松手是否出现回弹、振荡、下坠或持续漂移。

### 7.2 跟随式柔顺目标

若 `q_target` 始终固定在进入示教时的位置，手臂被拖到新位置后会产生回弹趋势，不适合正式示教。优先考虑让目标缓慢跟随实际位置：

```text
初始 A
  → 人施力将手臂拖向 B
  → 实际关节 q 向 B 移动
  → q_target 缓慢跟随 q，保持中心逐渐移动到 B
  → 松手
  → 手臂保持在 B 附近
```

跟随速度必须受限，并结合关节限位、速度限幅和异常退出条件，防止噪声或突发外力造成目标跳变。

### 7.3 重力补偿

如果降低 `Kp` 后肩部或肘部因手臂重量明显下坠，再研究加入手臂重力补偿。重力补偿应在基础阻尼和目标跟随稳定后单独验证，避免一次引入过多变量。

## 8. 示教录制与打点

录制采用“完整轨迹 + 打点系统”：

- 后台连续记录手臂电机状态（至少包含时间戳、位置和速度，必要时保留控制参数及原始反馈）。
- 用户通过键盘记录 `P1`、`P2`、`P3` 等关键点。
- 点位本质是完整录制时间轴上的 marker，不是替代完整轨迹的独立数据。
- 原始录制数据必须始终保留。
- 裁剪、速度调整、轨迹生成和格式转换全部作为可重复生成的派生数据处理，不覆盖原始数据。

腿部和腰部的 `SIT_HOME` 保持数据与手臂录制数据逻辑分离；手臂动作录制不应改变坐姿基座目标。

## 9. 实机实验顺序与安全边界

优先进行小范围、低风险的单关节或单臂实验，并在确认安全后扩大到双臂：

1. 固定 `q_target =` 当前姿态，降低 `Kp`、调整 `Kd`，验证“有明显阻力但可以拖动”的手感。
2. 检查拖动后松手是否有回弹、振荡或下坠。
3. 若回弹明显，引入 `q_target` 缓慢跟随 `q_actual`。
4. 若下坠明显，再单独研究手臂重力补偿。
5. 柔顺示教稳定后，接入键盘打点和轨迹录制系统。

每一步都应设置关节角度、速度、力矩和工作空间限制，并准备人工急停/控制退出路径。腿部和腰部始终保持坐姿支撑，不得因手臂实验失去 `SIT_HOME` 保持。

## 10. 当前明确不做的工作

现阶段暂不引入复杂阻抗控制、IK、RL 或轨迹优化。首先验证以下核心问题：在腿部和腰部稳定保持坐姿的情况下，双臂能否实现稳定、安全、有明显阻力，但用户能够人工拖动并打点的 `TEACH MODE`。

## 11. 下一步研究问题

当前最重要的下一步是通过单关节和单臂实机实验，确定 G1 手臂 `TEACH` 模式的 `Kp/Kd` 可用区间，并判断目标跟随和重力补偿是否为必要组件。实验结果应记录为可追溯的参数配置和测试记录，再用于双臂示教及钢琴动作播放。
